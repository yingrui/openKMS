Product introduction

openKMS

Knowledge, data, and ontology in one system — so people and agents can research with evidence, then ship polished static presentations.

Product

One place for research work

Documents & wiki

Capture and revise institutional knowledge with searchable markdown.

Knowledge bases

Grounded answers with citations — ask, don’t guess.

Ontology & data

Object types, links, datasets, and Functions for operational facts.

Surfaces

Where evidence lives

  • Search across documents, articles, wiki, and KB content
  • KB ask for grounded narrative with citations
  • Ontology ask when you need graph-backed tables (columns / rows)
  • Datasets for tabular facts — metadata first, then paged rows
  • Functions for computed metrics exposed as callable APIs
Agents

Pull data only via the skill CLI

  • python scripts/cli.py … — no ad-hoc HTTP
  • JSON responses chain into the next call
  • Aggregate locally before you chart
  • Cite source ids next to every claim

Typical path

datasets metadata → datasets rows → optional ontology ask / kb ask → write HTML

Guide: references/research-report.md in the openkms skill

Reporting

Reveal.js + Plotly

  • Reveal owns slides, notes, overview
  • Plotly owns interactive charts
  • Figures stay standard {data, layout}
  • No fixed deck JSON schema — write HTML freely
Engineering tips

Make charts behave in slides

disableLayout

Avoid Reveal’s CSS scale fighting Plotly hover coordinates.

resize on change

Call Plotly.Plots.resize on slidechanged / fragmentshown.

Bundle size

Use plotly-basic unless you need 3D, maps, or finance traces.
